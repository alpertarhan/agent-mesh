# v0.7.0 — Message tracking and idle daemon shutdown

## Messaging

- `agm track MESSAGE_ID` shows whether mail is queued, what delivery the local
  broker can confirm, whether the recipient explicitly marked it seen, and the
  latest retained direct reply. Use `-json` for scripts. An adapter taking or
  acknowledging mail is not proof that a model read it; only the recipient can
  run `agm seen MESSAGE_ID`. Neither command wakes a model.
- Publish a recurring responsibility with `agm role set NAME DESCRIPTION`.
  Use `agm inspect TARGET` for the role, current task, host observations and
  delivery behavior. A role neither grants permissions nor routes messages.
- Pi and OMP can send longer text through the native tool without splitting it
  into multiple messages. The wire-size limit still applies; model previews stay
  bounded. Message cards distinguish requests from replies, adapt to narrow
  terminals, and show a reply action for requests.

## Integrations and delivery

Grok Build registers sessions and leaves mail in the inbox. Factory Droid and
Muse Code receive mail at session start and on prompts, without idle wake.
The OpenClaw plugin is no longer distributed. For remote access use `agm link`
or `agm link -bridge`.

Mailbox removals now report persistence failures rather than claiming success.
Codex wake delivery keeps mail on disk until the host accepts the turn. An
interruption after acceptance can cause redelivery; this is not exactly once.
Spawned sessions return results to the original parent ID even after a rename.

## Daemon lifecycle

Automatically started daemons can exit after about two minutes without work,
checked every 30 seconds. Open connections and outstanding work prevent sleep;
offline mail alone does not. The next client starts a successor. Run
`agm daemon` explicitly to keep it up. Unchanged session binds no longer rewrite
the entire spool on each read.

Each daemon now needs a private socket directory and exclusive use of its spool.
For multiple daemons, use separate directories rather than different socket
names in the same directory. A non-socket file at the socket path is not removed.

## Upgrade

1. Upgrade the binary using your usual installation method. Previously generated
   OpenClaw plugins are not managed by this upgrade; remove them through OpenClaw
   if you no longer use them.
2. Run `agm restart` and `agm refresh`. Refresh updates only previously managed
   integrations; the default daemon also runs it at startup. To add a new
   harness, use `agm install TARGET`. Review permissions in the host itself.
3. Restart harness sessions to load the new adapter. Use `agm status` to check
   installation and `agm list` to check connections. Upgrade both ends of a
   bridge before relying on new capabilities.
