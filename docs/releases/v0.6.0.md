# v0.6.0 — Native messaging and observable coordination

A stable, non-prerelease update for safer delivery, bounded peer context and explicit
coordination. Pi/OMP gain native messaging tools and runtime observations; the shared
CLI remains available to every harness.

## Highlights

### Native messaging and safe retries

- Pi/OMP expose `agent_mesh` for send, asynchronous ask and reply, with separate
  recipient, summary, details, constraints and literal file-path fields.
- Native sends return compact `broker_accepted` receipts and a `request_key`. Reuse
  the same key with identical fields after an uncertain outcome. CLI users can opt
  into `-key TOKEN -receipt`; legacy send output is unchanged.
- Deduplication persists across daemon restarts for the broker's last 4096 accepted
  keyed sends. It is sender-scoped, bounded, and not end-to-end bridge exactly-once
  delivery. Acceptance does not prove reading or task completion.
- Tool parameters are checked against the adapter's declared limits. Hosts such as
  OMP may normalize model arguments before the extension receives them.

### Discovery, presence and linked tasks

- `list -state ... -metrics`, `inspect` and `watch` expose current work, connection
  versus activity, selected/response model provenance, context estimates and
  last-request TPS/TTFT with units, sources and freshness.
- Pi/OMP sample native idle state rather than treating `agent_end` as final idle.
  Abort, retry and recovery paths no longer produce that premature idle signal.
  Missing data stays `unknown`; silence is not diagnosed as a stuck agent.
- `task set -request MESSAGE_ID -state accepted '<summary>'` links a task to an
  incoming request. Later `working`, `blocked` and `done` updates retain the link
  and omitted scope. This is one owner-declared task snapshot, not a scheduler,
  lock or status journal.
- Task changes are metadata-only: they do not wake models, ACK mail or fulfill an
  ask. Send results through a normal reply, even after declaring `done`.
- Idle Pi/OMP session renames reach the broker without requiring a model turn.

### Bounded automatic delivery

- Automatic peer previews are bounded to **8000 UTF-8 bytes per message** and
  **24000 bytes per batch/run window**, including headers, attachments and hints.
  Pi/OMP, OpenCode, OpenClaw and hook/Codex delivery paths enforce their applicable
  total budgets, not just a body-length cutoff.
- Atomic selected-message consumption leaves unselected mail queued. Pi/OMP retain
  excess unacked; OpenCode counts input attempts, including ambiguous retries,
  against its observed-run budget. OpenClaw bounds every inbound body field and
  serializes per-peer turns.
- Excess delivery is conservative on older hosts: Pi/OMP can resume on the next
  natural run, while OpenCode without completion snapshots requires session
  reselection after its quota is exhausted. Interrupted runs do not release backlog.
- Full bodies remain available through `show` while retained. These limits do not
  cap cumulative conversation history or explicit full-message reads.

### Reliability and compatibility

- Sends commit before delivery; persistence failures reject the send without
  publishing it. Bridge and OpenClaw delivery retry transient persistence failures.
- Daemon ownership survives GC and shutdown draining; cancellation interrupts
  blocked socket writes. Bridge deadlines cover writes as well as reads.
- Pi/OMP ACK at host message/turn persistence boundaries; unpersisted handoffs
  remain queued across session switches. Delivery is still at least once, not a
  power-loss or exactly-once guarantee.
- Shared integration configuration and backup permissions are preserved, and
  malformed trailing JSON is rejected.
- Protocol remains **2**. Optional `coordination`, `idempotency`, `take_ids` and
  `task_lifecycle` capabilities are negotiated before using their new behavior.
  Older daemons are refused where silently ignoring a field would be unsafe.

## Upgrade

Update through your existing installation method. For Homebrew, once the tap's
bottle publication has completed:

```sh
brew update
brew upgrade alpertarhan/tap/agent-mesh
agm install
agm version
agm status
```

For npm/Bun, update `@alpertarhan/agent-mesh` to `0.6.0`, then run `agm install`.
Standalone users can rerun `install.sh`; it verifies the release checksum.

`agm install` refreshes detected integrations and restarts a running daemon from the
new binary. Reload or start fresh harness sessions so the new adapter code loads;
replacing the binary alone does not replace an already-loaded extension. Existing
queued mail is preserved; do not delete the socket/spool directory to upgrade.
Apply the upgrade and restart on both hosts of a bridge when using new capabilities.
Other harnesses remain usable, with unknown runtime observations where unsupported.

## Verification and boundaries

- Full formatting, vet and race-enabled suite passed locally, including installed
  SDK checks; the complete run took 796 seconds.
- Real Pi 1.4.0 and OMP 17.3.5 SDK session/extension lifecycles were tested with an
  isolated broker, fresh HOME/config/data directories and a deterministic fake
  model stream. Checks cover native tools, invalid required parameters, keyed
  retries, idle rename, busy/idle delivery, persistence/ACK, terminal errors and aborts.
- OpenCode 2.1.4 API schema was inspected in isolation. OpenCode/OpenClaw behavior
  also has adapter-specific fixtures; this is not a claim of real-provider or
  complete interactive-UI verification.
- No credentials were inherited by the installed-SDK fixtures; network requests
  were blocked. Live-provider validation remains separate from these checks.
